# 08: Hazard Events

**What to build:** Random, terrain-gated Fire/Flood events during the hazard-roll phase, each rolling 50/50 between damaging and destroying the building they strike.

**Blocked by:** 02 (Map Terrain Generation), 04 (Building Placement)

**Status:** ready-for-agent

- [x] During the hazard-roll phase, there's a chance each turn that a Fire or Flood event strikes a tile with a building on it
- [x] Fire only strikes buildings on Volcanic or Forest tiles; Flood only strikes buildings on River/Water-adjacent tiles
- [x] Each hazard event rolls 50/50 between damaging (temporary output reduction) and destroying the building outright
- [x] A damaged building's output recovers automatically after its temporary penalty expires

## Comments

Implemented via `src/systems/HazardSystem.ts` (new file), registering on `TurnManager`'s `hazardRoll` phase — same constructor-injection/`registerWithTurnManager()` shape as `PopulationSystem`. It depends only on a small structural `HazardBoard` interface (`getTerrainAt`, `getAllBuildingTiles`, `destroyBuildingAt`, `placeBuildingFree`), which `GameBoardScene` already satisfies, so it's constructed as `new HazardSystem(this, () => this.turnManager.getTurnNumber())`.

Each `hazardRoll` tick first resolves any due restores (see below), then rolls `HAZARD_CHANCE` (placeholder: **15%**, documented in-file as the flat per-turn base rate — Age-based frequency scaling per documentation.md §8 is explicitly a later ticket). On a hit, it builds the union of Fire-eligible tiles (building sits on a Volcanic or Forest tile) and Flood-eligible tiles (building is 4-directionally adjacent to a Water tile — a small helper `isAdjacentToWater` mirroring `BuildingPlacement.ts`'s `hasWaterBonus` pattern, generalized off Farm), picks one uniformly at random from that union, and rolls 50/50 destroy vs. damage. If no tile is eligible for either hazard that turn, it skips silently, per spec.

**Destroy** calls `destroyBuildingAt` directly (permanent). **Damage** also calls `destroyBuildingAt` immediately, but first remembers `{row, col, type, dueTurn: currentTurn + DAMAGE_RECOVERY_TURNS}` in an internal pending-restores list; `dueTurn` uses a placeholder of **3 turns** (documented in-file). At the start of every subsequent `hazardRoll` tick, any pending restore whose `dueTurn` has arrived gets rebuilt via `placeBuildingFree`. This keeps the "damaged and non-functional" state a pure absence of the building — no other system (Farm/Population production, etc.) needed any changes to support it.
